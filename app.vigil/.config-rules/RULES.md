# RULES — app.vigil Build & Config

> For AI agents. Governs app.vigil's root build/config files (they live at the project root
> where toolchains expect them; this folder holds their shared contract + changelog).

## Files governed

`vite.config.ts`, `eslint.config.ts`, `tsconfig.json` / `tsconfig.app.json` /
`tsconfig.node.json`, `.prettierrc.json`, `env.d.ts`, `components.d.ts`,
`.vscode/settings.json`.

## Intentional Decisions

- **`vite.config.ts` owns the module aliases** (`@AuthModule`, `@UserModule`, `@Helpers`,
  `@Composables`, etc.). Adding a module = add its alias here AND in `tsconfig.app.json`
  `paths` — the two must stay in lockstep or imports break at build vs. type-check time.
- **`unplugin-vue-components` auto-imports** everything under `src/components/*`,
  `src/modules/*`, `src/layouts/*`, plus PrimeVue via `PrimeVueResolver`. This is why Vue
  components are never imported in `<script setup>` — see `celer-02-vue-imports`.
  `components.d.ts` is GENERATED by this plugin — never hand-edit it.
- **`eslint.config.ts` is the enforcement engine** for most conventions (import order via
  `perfectionist`, `import type`, attribute order, `no-else-return`, empty-catch, locale
  JSON sorting). Convention rules that are `[ESLint]`-tagged in `celer-01` live here.
- **Prettier + `prettier-plugin-tailwindcss`** owns Tailwind class ordering — never order
  classes by hand.
- **tsconfig is split**: `tsconfig.json` (solution/refs) → `tsconfig.app.json` (app code,
  holds `paths`) + `tsconfig.node.json` (vite/build tooling). Put app path aliases in
  `tsconfig.app.json`, not the root.

## Do Not

- Do not hand-edit `components.d.ts` (generated).
- Do not add an alias to vite without mirroring it in `tsconfig.app.json` paths.
- Do not relax ESLint rules to silence a convention violation — fix the code.
